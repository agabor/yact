Limitations

YACT does a narrow job and gives up a lot to do it. This page lists what it does not do, where it works badly, and what is known to be broken. For anything else, open an issue.

  • What it does not do
  • Where it works badly
  • Known issues

What it does not do

  • It does not prove a change is correct. The lint shows the gaps in the prompt that the model noticed. It can miss some, and a plan with no Assumptions section may still rest on one. Reading the plan, reading the diff and running the tests are still needed.
  • It does not find context for you. You link the files. If you do not know which code a change touches, an agent that explores the repository is the better tool.
  • It does not run tests or iterate. One call writes the code; checking it is up to you.
  • It does not run unattended. There are no workflows, by design.
  • It does not make anyone read. A tick is one keystroke.
  • It does not attach the plan to the change. Committing it or pasting it into the pull request is up to you.

Where it works badly

  • Large files. The model writes every changed file back in full, within the model's output limit. YACT warns about linked files over 300 lines. A codebase of very large files is hard to work with.
  • Large changes. A plan is implemented in one call. A change that does not fit has to be planned as several smaller ones.
  • Legacy code. Tangled code needs many linked files per step, and act does not refactor code the prompt did not ask about.
  • One provider. Only Anthropic's API, with your own key. No other providers, no local models.
  • Index coverage. The index of names covers Go, PHP, JavaScript, C#, Swift and Kotlin. In other languages, such as TypeScript or Python, the model is less able to ask for code it was not given.
  • Noisy diffs. Whole-file output can change more lines than the task needed. Nothing in YACT limits the size of a diff.

Known issues

The missing-context loop
Rarely, y plan keeps listing the same files under Missing context while nothing else changes. YACT keeps no conversation history, so the model does not know it asked before. Fix: delete the section by hand and run y act; if a step then lacks context, link the file yourself.
Links into ignored folders are writable
A response may only write linked files, but a link to an existing file inside an ignored folder (such as .git/hooks/pre-commit) is treated like a new file and allowed. Do not link into ignored folders.
Old prompt copies
A system prompt downloaded before 2026-11-20 may contain --strict, which no longer exists, and fails with unknown flag: --strict. Run y download prompt act to get a current copy.
The feedback note is not cleared
.yact/temp/feedback.md stays between calls, so an old note can look new. Delete it before a new change.
.yact/plans/ from older versions stays
If you used split, delete the folder; nothing reads it any more.
