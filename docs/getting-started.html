Getting started

About ten minutes from nothing to a first reviewed change.

What you need

  • A terminal and a Git repository to work in. YACT writes files into your project, so use a working tree where you can review changes and undo them.
  • An Anthropic API key, created in your own account at console.anthropic.com. It is pay-as-you-go, so the account needs some credit. YACT prints an estimated cost after every call.
  • Either the Go toolchain, to build from source, or a prebuilt binary for your platform.

Install

Build from source (recommended)

YACT is written in Go, so building from source means you run code you can read.

git clone https://github.com/agabor/yact.git
cd yact
go build -o y .
mkdir -p ~/.local/bin
mv y ~/.local/bin/

Make sure ~/.local/bin is on your PATH. The repository also has an install.sh that builds the binary and installs it to /usr/local/bin with sudo.

Prebuilt binary

Download the file for your platform from the releases page.

PlatformFile
Linux (x86-64)yact-linux-amd64
macOS (Apple silicon)yact-darwin-arm64
macOS (Intel)yact-darwin-amd64
Windows (x86-64)yact-windows-amd64.exe

On Linux and macOS, make it executable and put it on your PATH under the name y:

chmod +x yact-linux-amd64
mkdir -p ~/.local/bin
mv yact-linux-amd64 ~/.local/bin/y

On Windows, put yact-windows-amd64.exe in a folder on your PATH, or run it from where you downloaded it.

Configure

Save your key. It is written to ~/.yact/config on your machine and used only for calls to Anthropic's API.

y config anthropic_api_key <your-own-anthropic-key>
y config

The second command shows your current settings, so you can check that it worked. Then download the official system prompts:

y -d act
y -d plan
y -d ask
y -d bash

Every system prompt is a plain text file in ~/.yact/systemprompts/, and every file there becomes a command: act writes code, plan writes a plan, ask answers questions and bash writes shell commands. Read them whenever you like.

Finally, keep YACT's task state out of your commits. In the repository you work on, add this to .gitignore:

.yact/

The plan lives in yact-prompt.md. Whether it is committed or attached to a pull request is up to you, so ignore it only if your team does not want plans in the repository.

Make your first change

This walk-through uses a plan, so you read what will change before any code is written. Run it inside a Git repository.

  1. Start clean. This removes any earlier task file and message files.

    y new

  2. Pick the files the task needs. Quote glob patterns so your shell does not expand them first. Each file is added to yact-prompt.md as a link. To add every file that contains a word instead, use y keyword Transaction.

    y read main.go
y read "commands/*.go"

  3. Ask for a plan. The response is saved to yact-prompt.md instead of your source files. Open it, read it and edit anything you disagree with. Each step changes one file and ends with a Context line that lists the files that step needs.

    y -p plan "add a --version flag"

  4. Implement the first step. YACT sends the goal and that one step, makes one API call, writes the files and ticks the step off in the plan.

    y -s next act

  5. Review the change. Read the diff as you would read a colleague's. If it is wrong, fix the plan or the code and try again.

    git diff

  6. Repeat. Run steps 4 and 5 until YACT prints All plan steps are done.

A quicker path for small changes

You can skip the plan and give the task directly. The files you added with y read, and any paths you mention, are sent as context.

y read main.go
y act "add a --version flag"

Read a response before it is written

With -n, YACT prints the response instead of writing files. Apply it later with y commit when you are happy with it.

y -n act "add a --version flag"
y commit

Choose a model

act uses Haiku by default. Add -c 2 for Sonnet, -c 3 for Opus or -c 4 for Fable. Which models you can use depends on your Anthropic account.

Ask without changing anything

The ask command answers questions about the files you pick and never writes to your source files. It is a good way to understand a codebase before you change it.

y new
y read commands/call.go
y ask "why does this function return early?"

For a bigger picture, add a code index with -i. Level 1 lists public declarations and level 2 lists all of them.

y -i 1 ask "where is the config loaded?"

See what is sent and what it costs

Before each call YACT prints Input lines: <n>, the total number of lines it is about to send. If that is more than max_input_lines (2000 by default), the call is refused. After the call it prints the model, the duration, the token counts and an estimated cost.

To see exactly which files go out, add --verbose:

y --verbose ask "how does the parser work?"

A file is sent when its path appears anywhere in your task text, so a stray mention can pull in more than you meant. If the total is too large, run y new and add only the files you need, or raise the limit for one call with -m 3000.

Use it with a team

Plans in reviews. A plan shows what a change was meant to do, step by step. Commit it, paste it into the pull request description, link to it or keep it local. YACT does not prescribe a way, so the person leading the team decides.

Mentoring. If you are learning, write down what you expect each step of a plan to change before you run it, then compare with the diff. If you are mentoring, ask for the plan first and review it before any code exists.

Shared commands. A command is a text file in ~/.yact/systemprompts/, so a team can share review.txt or explain.txt like any other file. See how.

When something goes wrong

Claude API key not configured
Set your key with y config anthropic_api_key <your-own-anthropic-key>.
input exceeds maximum number allowed lines
Start over with y new and add only the files you need, select fewer plan steps with -s, or raise the limit with -m.
no system prompt found for command
Download it with y -d <command>, or create the file in ~/.yact/systemprompts/.
response contains free text outside code blocks
This comes from -v, which act turns on by default. Run the command again, or read the rejected response in .yact/buffer.txt. Nothing was written to disk.
